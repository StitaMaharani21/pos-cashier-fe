# modules/owner/dashboard

Owner landing screen after login, matching the Figma dashboard design (Neela / Asta Studio file). Backed by `pos-kasir-be`'s real analytics endpoints — no mock data. Each widget is its own component wired to one endpoint via `dashboard.queries.ts`.

Still a deliberate exception to the `CrudSection`/`createCrudService` pattern used by the rest of `modules/owner/*`: there's no form/table to manage, just read-only widgets (plus one small write action), so each widget owns a small `useQuery` hook instead.

- `dashboard.queries.ts` — one `useQuery` per GET endpoint (`useDailyTransactionLimit`, `useDashboardSummary`, `useCashSummary`, `useRefundSummaryToday` (no longer used by the KPI grid — refunds now come from the shift summary), `usePopularMenu`, `usePaymentMethodValueBreakdown`, `useSalesTrend`, `useLowStockMenus`, `useOrderComposition`) plus `useRecordCashCount` (a `useMutation` for `POST /shifts/:id/cash-counts`, invalidating the cash-summary query on success) and `useCloseShift` (`PATCH /shifts/:id/close` with `{closing_balance, closing_notes}`; returns the reconciliation: `expected_balance`, `difference`, `difference_status`).
- Cash rules (same formula as the backend's `shift.ExpectedCash` and Laporan Kas): Kas Awal is never revenue; Total Cash = sum of order totals paid in cash (not the tendered amount — change is just a swap); `Total Pendapatan = Cash + Non-Cash − Refund`; `Kas yang Diharapkan = Kas Awal + Cash Sales + Cash In − Cash Out − Cash Refund`; `Selisih = Kas Aktual − Kas yang Diharapkan` (green = sesuai, amber = surplus, red = shortage). `CloseShiftDialog` shows the live difference and requires a note when it isn't 0.
- **Catat Kas** (`components/CashMovementDialog.tsx`, `schemas/cash-movement.schema.ts`, `useRecordCashMovement` → `POST /shifts/:id/cash-transactions`): Kas Masuk / Kas Keluar outside a sale on the running shift, with a required explanation. It changes `Kas yang Diharapkan` (`Kas Awal + Penjualan Tunai + Kas Masuk − Kas Keluar − Refund`; every refund is paid in cash from the drawer, whatever the original payment method) immediately — the backend bumps the shifts sync version on every `trx_cash_transaction` write so the cached dashboard summary refreshes. The button sits in the "Rekonsiliasi Kas Laci" header and only shows while a shift is open; **Kas Aktual and Selisih Kas are hidden when no shift is open** (they belong to a running shift and reset for the next one).
- `schemas/cash-count.schema.ts` — zod schema for the "hitungan kas fisik" dialog form.
- `components/` — one presentational component per widget: `TransactionLimitCard`, `KpiCard` + `KpiCardsGrid` (top stat cards for the **currently open shift**, `since_shift_open=true`, in two groups — *Ringkasan Penjualan*: Total Pendapatan, Total Pesanan, Total Cash, Total Non-Cash, Total Refund; *Rekonsiliasi Kas Laci*: Kas Awal, Kas yang Diharapkan, Kas Aktual (clickable → `CashCountDialog`, with "Tutup Shift"), Selisih Kas), `CashCountDialog`, `PopularMenuTable`, `PaymentMethodDonutCard` (Recharts donut), `SalesTrendCard` (Recharts bar+line combo with a 7/30-hari toggle), `LowStockCard` (`GET /master/menus/low-stock`, **every plan** incl. Starter: menus tracked per menu — `by_menu` — at/below their `low_stock_threshold`; red when down to half the threshold or out, amber otherwise, first 5 then "+N menu lainnya"), `OrderCompositionCard`.
- `section/DashboardSection.tsx` — composes everything in the Figma layout (Limit → KPI grid → Menu Terpopuler + Metode Pembayaran → Penjualan chart → Stok Hampir Habis + Komposisi Order).

Endpoint DTOs live in `entities/order/model/order-analytics.types.ts`, `entities/shift/model/shift.types.ts`, `entities/refund/model/refund.types.ts`, and `entities/menu/model/menu.types.ts` (`LowStockMenu`) — all re-exported from the generated `owner-schema.d.ts` (see `scripts/generate-owner-types.mjs`'s `ALLOWED_PATH_PREFIXES`).

**On-screen wording** (plain Indonesian, no accounting terms): "shift" is shown as *sesi kasir* / "Tutup Kasir"; Kas Awal → *Uang Modal Awal*, Kas yang Diharapkan → *Uang Seharusnya Ada*, Kas Aktual → *Uang Hasil Hitung*, Selisih → *Uang Kurang/Lebih* (*Uang Pas* / *Uang Lebih* / *Uang Kurang*), Rekonsiliasi Kas Laci → *Uang di Laci*, Cash/Non-Cash → *Tunai/Non-Tunai*. Order types come from `shared/lib/order-type-label.ts`. The word "Refund" is kept on purpose. Code, field names and test ids keep the old names.
